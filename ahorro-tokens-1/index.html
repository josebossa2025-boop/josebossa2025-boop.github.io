Ahorro de tokens en Claude Code 1/3 — RTK y compresión semántica

Repaso del video 1 de la serie de ahorro de tokens en Claude Code: RTK y compresión semántica — recorta hasta la mitad de tus tokens sin perder calidad.

Al terminar vas a poder: Instalar RTK y poner tu CLAUDE.md a dieta para que cada sesión de Claude Code gaste menos desde hoy.

Lo clave en 3 ideas

  • Gestión de tokens = gestión de contexto: cada token basura cuesta doble — dinero y atención del modelo.
  • RTK es un proxy que se engancha con un hook PreToolUse: reescribe cada comando Bash (git status → rtk git status) y comprime el output antes de que entre al contexto. Solo aplica al tool Bash; espera 30-50% real por sesión.
  • Comprimir no es resumir: la compresión semántica conserva TODO el significado en menos palabras. Si Claude obedece igual, comprimiste; si perdió algo, resumiste.

Pon a prueba lo que entendiste

Responde mentalmente antes de abrir la respuesta.

01¿Por qué un token basura cuesta doble?
Porque lo pagas en la factura Y diluye la atención del modelo: el contexto es un recurso finito, y el ruido compite con la señal de lo que sí importa.
02¿Qué hace el hook PreToolUse de RTK y dónde NO aplica?
Reescribe cada llamada Bash automáticamente (git status → rtk git status) para que el proxy filtre, agrupe y deduplique el output. No aplica a los tools nativos Read, Grep y Glob — solo a Bash.
03¿Cuál es la prueba de fuego de la compresión semántica?
Reescribir con el mismo significado en mínimas palabras y verificar: si Claude sigue todas las instrucciones igual que antes, comprimiste; si algo se perdió, resumiste. En la demo: 865 → 211 palabras sin perder una instrucción.
